# 一、负责人决策（本轮直接生效）

## D1：hidden observation 本轮不批准

本轮 **不批准** 读取任何框架内部字段或调用任何非 SDK 接口，包括但不限于：

* `Application.mLoadedApk`
* `LoadedApk.*`
* `ContextImpl.mPackageInfo`
* `ActivityThread` 的 `mPackages` / `mResourcePackages`
* `ActivityThread.getPackageInfoNoCheck`

在 B0 结果中，这些项统一标记：

```text
HIDDEN OBSERVATION = DEFERRED (NOT APPROVED IN TASK-14)
```

不写反射代码，不引入 hidden API bypass 库。

理由：

* 项目默认策略（design/20）是不使用 hidden API。
* B0 要回答的核心问题是「Guest 代码和 Host 实际会看到什么后果」。这些后果大部分可以通过 **PUBLIC API 的行为** 直接观测，不需要读内部字段。
* 只有在 PUBLIC 观测无法区分两种假设时，才申请 hidden observation，并且要单独写申请，列清字段、目的、只读方式和清理方式。

## D2：B0 以 PUBLIC-ONLY 模式执行

本轮执行的实验命名为：

```text
EXP-003B0-P（Public-only Host LoadedApk impact observation）
```

同时把 precheck 状态从：

```text
NEEDS_MORE_RESEARCH
```

更新为：

```text
READY FOR B0-P (PUBLIC-ONLY); HIDDEN OBSERVATION DEFERRED
```

## D3：Controlled Context 的底座改为 Host Application Context

ADR-0008 记录的是：

```text
BASE_CONTEXT = HOST（MainActivity）
```

B0-P 中，Controlled Context 的 base 必须改为：

```text
hostActivity.applicationContext
```

理由：

* `Application.attach()` 会通过 `ContextImpl.getImpl()` 剥开 ContextWrapper 链，取最底层的 ContextImpl。底座是 Activity 时，取到的是 **Activity 的 ContextImpl**，会带上 Activity 的语义和生命周期。
* Guest Application 的生命周期长于任何一个 Host Activity，用 Activity 做底座会造成泄漏。

EXP-003A 的 C0 结论不需要因此重做。但 B0-P 必须把 Activity 底座作为 **对照组** 跑一次，并记录两者差异。

## D4：Instrumentation 使用公开构造

使用：

```kotlin
val instrumentation = Instrumentation()
```

不要尝试获取进程真实的 Instrumentation。

源码（android-36 `Instrumentation.java`）显示：app 自己创建的 Instrumentation 的 `mThread == null`，`newApplication()` 内部的 `getFactory()` 会：

```text
输出错误日志 "Uninitialized ActivityThread, likely app-created Instrumentation, disabling AppComponentFactory"
返回 AppComponentFactory.DEFAULT
```

这是预期行为，不是失败。必须记录这条日志。

它带来一个兼容性后果：**Guest manifest 中声明的 `android:appComponentFactory` 不会被使用。** 很多使用 AndroidX 的应用在 manifest 合并后都带有 `androidx.core.app.CoreComponentFactory`。本轮要用 GuestTestApp 实际验证这一点（见第三节）。

## D5：同 package 多实例

本轮 **只设计，不执行**。写入独立的计划文档（见第七节）。

## 4.1 Guest Application

新增：

```text
com.example.appsandbox.testguest.runtime.Exp003GuestApplication
```

```xml

```

要求：

* 构造函数中递增一个 **静态** 计数器（用于以后多实例对照）
* 重写 `attachBaseContext(base)`：记录 `base` 的类名、`base.packageName`，调用 super
* 重写 `onCreate()`：只做一件事——设置一个静态标志 `onCreateCalled = true`。本轮 Host 绝不调用它，最后要验证这个标志仍为 false

  * `this.classLoader` 类名
  * `this.resources` 是否能读到 Guest 自己的 `R.string.exp002_string`（用 Guest 的 R，在 Guest 代码里）

  * `this.opPackageName`
