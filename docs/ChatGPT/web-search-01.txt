docs/research/virtualization/01_TECHNOLOGY_LANDSCAPE_2026.md

至少研究以下几类。

---

## Route A — Application-level Virtualization

目标：

普通 Host App 中运行：

未安装 Guest APK。

典型能力：

* Guest APK Registry
* Dex/ClassLoader
* Resources
* Component virtualization
* PackageManager compatibility
* Activity/Service/Provider virtualization
* Binder/SystemService translation
* Multi-instance
* Storage mapping

研究：

这种路线到 Android 16 是否仍然现实。

---

## Route B — Plugin Framework

例如：

Host 控制插件 APK。

研究：

它与：

arbitrary third-party APK virtualization

有什么根本区别。

重点研究：

* RePlugin
* Shadow
* VirtualAPK
* DroidPlugin
* 其他现代插件框架

重点不是代码。

而是：

它们解决问题的边界。

---

## Route C — Work Profile / Managed Profile

研究：

Android Enterprise

Work Profile

Managed Profile

DevicePolicyManager

是否可以实现：

真正系统级：

* 独立 package install
* 独立 UID
* 独立 data
* 多实例

研究：

普通 Google Play App 能做到什么。

需要哪些：

Device Owner
Profile Owner
用户授权

与 AppSandbox application virtualization 的优缺点对比。

---

## Route D — Android Multi-user

研究：

Android User / Profile

能否作为多实例容器。

普通第三方 App 权限边界。

是否需要：

system privilege
adb
root
device owner

---

## Route E — Android Virtualization Framework

研究：

AVF
pKVM
Microdroid

重点回答：

* 它是什么
* Android 哪个版本开始
* 第三方普通 App 是否能使用
* 需要什么 permission
* 是否可以运行完整普通 Android APK
* 是否适合 Play App

不要因为名字叫 Virtualization：

就与 VirtualApp 混淆。

---

## Route F — Full Android VM / Emulator

例如：

完整 Android guest OS。

研究：

* QEMU
* Cuttlefish
* emulator
* containerized Android
* Redroid 类技术

为什么通常不适合普通手机 App 内运行。

---

## Route G — Root / Xposed / LSPosed

研究：

root 环境下：

方法 Hook

ClassLoader injection

framework interception

相比无 Root virtualization 的能力差异。

重点明确：

哪些方案：

必须 root。

哪些：

可以无 root。

---

## Route H — Native virtualization / interception

研究：

* PLT/GOT hook
* inline hook
* linker interception
* libc syscall interception
* Binder ioctl interception
* seccomp
* seccomp-bpf
* seccomp-notify

* `/proc` compatibility
* linker namespace
