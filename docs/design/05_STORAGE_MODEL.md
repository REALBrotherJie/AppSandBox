# Guest Storage Model

## Goals

Storage must provide deterministic per-instance paths, atomic import, cleanup after failure, no path traversal, and a migration point for future quotas/encryption. It is logical isolation inside the host app's private storage, not a kernel sandbox.

```text
filesDir/
  guests/
    packages/
      <package-key>/
        revisions/<revision-id>/base.apk
        revisions/<revision-id>/metadata.json
        shared-resources/
    instances/
      <instance-id>/
        data/files/
        data/databases/
        data/shared_prefs/
        data/no_backup/
        cache/
        code_cache/
        native/<abi>/
        state/
    registry.json
```

`PROPOSED`: package/revision files are shared read-only where safe; instance directories are never shared. A content digest, not packageName, names immutable revision storage. The instance ID is opaque and generated by the host.

## Mapping

| Android concept | AppSandbox mapping |
|---|---|
| `dataDir` | instance `data/` |
| `filesDir` | instance `data/files/` |
| databases | instance `data/databases/` |
| shared preferences | instance `data/shared_prefs/` |
| cacheDir | instance `cache/` |
| codeCacheDir | instance `code_cache/` |
| nativeLibraryDir | instance or shared extracted native root |
| APK/code path | immutable package revision |

Guest packageName must never become the directory name without validation. Package name and instance ID are independent:

```text
com.example.app
  -> instance-A
  -> instance-B
```

## Security rules

- Resolve all paths under the host root and reject escaping canonical paths.
- Extract archives with entry count, size, compression ratio, and path limits.
- Write imports to a temporary directory, fsync/rename where appropriate, then publish registry state.
- Do not follow symbolic links during extraction.
- Treat guest native code as executable untrusted input.
- Define deletion as instance teardown plus registry transaction.

`RESEARCH NEEDED`: practical file locking and crash consistency on target OEM filesystems; encryption and quota strategy.
