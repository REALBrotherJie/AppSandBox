# 08 复杂应用抽测结论（阶段 4、13–17）

在 Mi10 / Android 12 / arm64 上对真实头部 app 的抽测结论。**目的是识别"通用 bug"与"app 专属深度对抗"的分界。**

## 通过的应用

| 应用 | 结论 | 关键修复 |
|---|---|---|
| 超级用户列表 `com.topmiaohan.superlist` | ✅ 完整运行 | 基础启动闭环（阶段 2） |
| 环境检测 demo `com.reel.applicationreversedemo3` | ✅ Risk 5/100 (LOW)，未识别在容器内 | 反检测（阶段 5–10） |
| **酷安** `com.coolapk.market`（网易加固、多进程、腾讯推送/微博/多广告 SDK） | ✅ 主界面+信息流联网、多进程独立 | NSC 明文（9）、AttributionSource、opendir/`__open_2` 重定向、JobScheduler、外部存储 |
| **WPS**（Tinker 热修复、多进程文档进程） | ✅ 可新建/编辑文档，多进程无崩 | ContentObserver 吞异常（15）+ AttributionSource 提前到 attachBaseContext 前（16） |
| Unity 游戏 Sudoku Cat Quest（Firebase/AppsFlyer/AppLovin） | ⚠️ 过 Firebase 依赖墙进入游戏 Activity | WebView AttributionSource（13）、signingInfo（14）、MicroG+uid 归因（GMS 项目） |

## 撞墙的应用（app 专属深度对抗，未攻）

| 应用 | 墙的类型 | 现象 |
|---|---|---|
| **微博** | 原生反篡改 | ContentObserver 崩溃已修（15），但 `SLib.nativeInit` 的安全 so 检测到沙箱、`JNI_OnLoad` 拒绝注册符号 → `UnsatisfiedLinkError`。so 加载成功但符号不注册，是典型 native 反沙箱。 |
| **京东** | 反 VA 自退 | Application 能起（MultiDex/MMKV/DrmHal 都过），但安全线程随后 `System.exit(0)` 静默自杀，无崩溃/无检测日志。拦截 Guest 的 `System.exit` 有风险（app 可能半初始化不可用），未做。 |
| **微信** | GMS 墙 + 深度初始化 | Tinker 修复（16）后过了 Application 创建，但主线程反复 `Failed to find provider info for com.google.android.gsf.gservices`，约 2 分钟无活动=卡死黑屏。根子在 GMS/GServices 不可用 + 微信深度初始化。 |
| Unity 游戏（进入后） | 广告 SDK | AppLovin 中介的 Mintegral `collectSignal` 绑定服务 `DeadObjectException`，游戏全局崩溃处理 kill 自身。属广告 SDK 兼容，与 GMS 无关。 |

## 关键分界原则

1. **通用 bug** = 由"沙箱没跟上 Android 版本/没模拟真实 PMS 行为"造成，修一次利好一大批 app：
   AttributionSource、系统服务改名、signingInfo、动态广播权限、NSC、ContentObserver、JobScheduler。
   **这些值得修。**
2. **app 专属深度对抗** = app 自己主动检测并拒绝运行：
   - **原生反篡改**（native 层读 apk/校验签名/检测 uid 与包不符 → 拒绝注册 JNI）：微博、微信同类。
   - **反 VA 自退**（检测到异常静默 `System.exit`）：京东。
   - **GMS 硬件/远程认证**（SafetyNet/Play Integrity）：MicroG 也给不了。
   **这些是 app 一对一的高成本对抗，通常不值得攻，除非该 app 是核心目标。**

## 一个反直觉现象

酷安在文件隔离**真正生效之前**"能跑"，恰恰是因为重定向是死的、从未真正隔离——
一旦重定向活了，它的加固逻辑不适应重定向后的路径反而 native 崩溃（阶段 6）。
**"正确性"会激活此前被掩盖的对抗逻辑。** 做对了基础反而可能触发新墙。

## 给 AppSandBox 的启示

- 抽测时把结果**按"墙的类型"归类**，而不是按"过/不过"。通用 bug 修，专属对抗记录并跳过。
- 头部国产 app（重加固）与强依赖 GMS 的 app 是这类沙箱的**共同前沿难点**，不是随手能过的。
- 用一个无依赖的探针 app（vaprobe：22 项功能自检打 PASS/FAIL 到 logcat）在沙箱内外对比，
  是定位缺口最省力的方式。
