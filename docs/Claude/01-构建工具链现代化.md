# 01 构建工具链现代化（阶段 1）

目标：让一个多年未维护的旧沙箱工程在现代工具链下**可编译、可安装、宿主可运行**，并支持 arm64。

## Java / Gradle 侧

- 目标基线：AGP 8.9.1 + Gradle 8.11.1 + `compileSdk/targetSdk = 36` + `minSdk 23` + NDK 27。
- **Support → AndroidX 迁移**。用自动迁移工具时要人工复核：迁移脚本会把一些**同名但非 support 库的类**
  误替换（实际踩到的：`Toolbar`、`CardView`、`AppCompat*`、`PopupMenu`、`ItemTouchHelper`）。迁移后要按包名核对。
- **移除失效第三方依赖**：Flurry、Once、SwitchButton 等旧库在现代 Gradle/AndroidX 下拉不到或不兼容，直接删。
  沙箱核心不应依赖这些统计/UI 小库。

## Native (NDK) 侧

现代 clang/NDK 对旧 C/C++ 代码更严格，几处典型修复：

- **VLA 报错**：fbjni 在新 clang 下对变长数组从告警变报错。把相关 flag 降回告警（`fb/Android.mk`）以先跑通编译。
- **`abs()` 歧义**：Substrate 里 `abs(im)` 在 C++ 里对某些类型有重载歧义，改为三元表达式显式判断。
- **arm64 缺 so ABI**：只有 armeabi-v7a 的第三方 native 库（如腾讯地图 `libtencentloc.so`）在 64 位进程会加载失败，
  相关功能（虚拟定位）要么换 64 位 SDK 要么移除。

## 运行期防崩（现代权限模型）

- **前台服务技巧限版本**：旧代码无条件用"启动前台服务保活"，在 Android 8+ 缺 `FOREGROUND_SERVICE` 权限会崩。
  改为**仅 Android 8 以下**启用该技巧。
- **hidden API 反射返回 null 的 NPE**：旧代码假设某些隐藏 API 反射总能拿到（如 WebView 相关），
  现代系统上返回 null 时不应直接打 NPE，加空判。

## 给 AppSandBox 的启示

- 起步就用高 `targetSdk`（本项目 36），能尽早暴露 scoped storage、后台启动限制、
  AttributionSource 等现代约束，而不是等到后期集中爆雷。
- native 层若要跨新旧 clang，先把"报错降告警"当临时手段跑通，再逐个真正修，避免一开始就卡在编译。
- 任何"保活/前台服务/隐藏 API"技巧都要**按 `Build.VERSION.SDK_INT` 分支**，旧技巧在新系统上往往是崩溃源。
