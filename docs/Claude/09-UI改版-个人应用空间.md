# 09 UI 改版：个人应用空间（阶段 22 / UI-01~06 已实现）

把旧的"三列瀑布流 + 拖拽 + 假 3 秒启动页"改成"安静、清晰、有个人标识"的工具型个人应用空间。
这部分**与沙箱内核解耦**，是纯宿主 UI，最适合直接迁移到 AppSandBox（且不涉及 clean-room 敏感项）。

## 视觉方向

- **Material 风格 + 自有蓝色主色**，浅色中性背景、低阴影卡片、大应用名、少量有意义状态标签；深色模式同等完整。
- 拒绝：玻璃模糊/全屏渐变/强动效（分散注意、增加渲染与可读性验证成本）。
- 重点是**语义颜色 + 清晰层级 + 可达操作 + 系统栏适配 + 可读性**，不是加装饰。

| 角色 | 浅色 | 深色 |
|---|---|---|
| background | `#F6F7FB` | `#111318` |
| surface | `#FFFFFF` | `#1C2028` |
| primary / onPrimary | `#315DA8` / `#FFFFFF` | `#ADC6FF` / `#102F60` |
| onSurface | `#1A1C20` | `#E3E5EC` |
| onSurfaceVariant | `#555F70` | `#B6BECC` |
| outline | `#747D8C` | `#8892A3` |
| error | `#BA1A1A` | `#FFB4AB` |

- 字号：页面标题 26sp / 区块标题 18sp / 应用名·正文 16sp / 辅助 12–14sp；应用名最多两行省略，详情展示全名。
- 间距 4/8/12/16/24/32dp，页面左右默认 20dp，卡片间隔 12dp。圆角：卡片 20 / 按钮 16 / 弹窗 24dp，卡片阴影 0–1dp。
- 图标操作 24dp，点击区 ≥48×48dp，应用图标 48dp。网格：手机两列，宽屏加列，大字体减列——**不要固定三列瀑布流**。
- 动效 150–250ms，尊重系统关闭动画，**动画不能阻塞真实完成结果**。
- 所有颜色必须经**主题角色**引用，逐步清理 Java 里的 `Color.WHITE`/`parseColor` 和 XML 硬编码色。

## 两个可复用的纯逻辑模型（已带单测）

这两个 model 与 Android 无关，是可读性/正确性的核心，**可直接照搬思路**：

### `AppSelection`（添加页多选，最多 9 个）

- **选择要在过滤、重排、屏幕重建后存活**。用稳定 key 标识：
  - 已安装应用：`installed:<pkg>`（更新后 apk 路径会变，用包名）。
  - 文件来源：`file:<pkg>\n<path>`（文件源需要精确路径身份）。
- `setApps` 后 `selected.retainAll(存在的 key)`，搜索只改可见列表不丢选中，`toggle` 到上限返回 false。

### `LauncherItems`（首页搜索视图）

- **搜索只是实例的视图，绝不替换其身份**。过滤态下禁止拖拽重排（`isFiltered()` 时 `move` 返回 false），
  避免可见索引与真实索引错位导致误操作。

## 关键交互原则（防"假状态"）

这些原则贯穿整个 UI 计划，是**诚实反映真实状态**的准绳：

- **只在真有请求进行中**才显示"正在添加/正在启动"；未观测到运行状态就不显示"运行中"。
- **没有真实进度源就不显示百分比**，用不定进度。等待久了提示"启动较长"，但**返回≠停止 Guest、超时≠断言崩溃**。
- 移除确认显示**完整应用名+空间名+真实数据影响**；不提供无法真正恢复数据的"撤销"。
- 快捷方式创建**无确认信号时不宣称成功**。
- 每次启动请求**独立关联实例**，防晚到回调关掉下一次启动界面；连续点击不重复提交。
- 同包多实例（多 userId）**不能只用颜色/角标数字区分**，每卡片显示空间名称。

## 给 AppSandBox 的启示

- UI 层与沙箱内核**天然解耦**，这套设计令牌 + 两个纯逻辑 model + 交互诚实原则可以**独立重写**，不触碰 clean-room 敏感面。
- 最有价值的不是配色，而是**"UI 不撒谎"的一组原则**（无真实进度不显百分比、无确认不宣称成功、返回不等于停止）。
- 多选/搜索的正确性靠"稳定 key + 过滤态禁重排"，值得先写纯逻辑单测再接 UI。
