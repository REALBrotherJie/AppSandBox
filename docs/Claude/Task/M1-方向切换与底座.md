## 验收标准

1. `docs/adr/ADR-0013-DIRECTION-A.md` 已写明放开项与禁止项（与 `AGENTS.md` 第 4 节一致）；`CLEAN_ROOM.md`、`27_NON_GOALS.md`、`README.md` 的冲突条款已更新（`00_SESSION_REQUIREMENTS.md` 已由规划者标记作废，无需再改）。
2. Task-58 未提交改动不入库（先 `git stash -u` 备份，不直接丢弃）。
3. 已移除：contract v1/v2、ActionSpec、`GuestActionViewBinder`、`GuestActivityCarrierActivity`、逻辑 Activity/Service store、dispatch 中只服务于逻辑组件的部分、`debug/experiments/*` 与对应 automation。保留：`GuestInstanceStore`/Registry、Resolver、runtime IPC 骨架、`GuestPackageReader`。
4. `applicationId` 改为下方"用户输入"中的包名（namespace 可同步修改）；release 签名配置读取本地未入库的 keystore 属性（`keystore.properties` 加入 `.gitignore`，缺失时 release 仍可构建为未签名包）。
   **若"用户输入"中包名仍为空：跳过改名，其余照常执行，并在回传中注明。**
5. hidden API 访问层：
   - 单一入口封装，不在业务代码里散落反射；
   - release 包在 API31 与 API36 上能读取 `ActivityThread.currentActivityThread()`、`mH`、`IActivityTaskManager` 单例等 M2 所需对象；
   - 失败时返回明确错误，不静默降级。
6. stub 组件：
   - manifest 预声明 `:p0`～`:pN`（N 先取 8～10）进程；
   - 每个进程配 stub Activity（standard、singleTop、singleTask、singleInstance，以及透明/对话框 theme 变体）、stub Service、stub Provider；
   - 宿主可以按需拉起指定 stub 进程，并能查询和回收；进程分配表由 runtime 进程持有。
7. 构建通过：`:app:testDebugUnitTest`、`:app:assembleDebug`、`:app:assembleRelease`。
