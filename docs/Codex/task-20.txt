# Task-20: API36 AVD 上线与 ACT-001 双版本闭环

当前审视结论：

```text
ACT-001 = PARTIALLY CONFIRMED
API31 L0 = CONFIRMED
API36 L0 = NOT EXECUTED
报告路径修复 = VERIFIED
ACT-002 = NOT AUTHORIZED
```

仓库和本机已知存在 API36 AVD：

```text
Pixel_3a_API_36_extension_level_19_x86_64
```

task-19 的主要阻塞是该 AVD 启动后没有进入 ADB，而不是 ACT-001 代码失败。

本轮目标只有两个：

1. 让 API36 AVD 真实进入 `adb devices` 并记录设备信息。
2. 在 API36 上复用现有 ACT-001 runner，完成真实 production GuestStore artifact 验证。

如果 AVD 仍不能上线，必须以环境阻塞结束，不得修改 Activity runtime，也不得进入 ACT-002。

## 一、硬性禁止

```text
不要实现 ACT-002。
不要实例化 Guest Activity extends Activity。
不要调用 Activity.attach。
不要创建 Stub Activity 或 Stub pool。
不要替换 Instrumentation。
不要拦截 ActivityThread、ClientTransaction、Handler 或 Binder。
不要使用 hidden API、内部反射、Hook、Xposed/LSPosed、native Binder 或 seccomp。
不要修改 app/src/main/ production runtime。
不要修改 ACT-001 逻辑，除非是 API36 启动所需的最小脚本兼容修复。
不要把历史 API36 证据冒充本轮 ACT-001 证据。
```

允许范围优先限制为：

```text
scripts/task20-*.ps1
docs/experiments/evidence/task20/
docs/experiments/TASK-20-ACT001-API36-RESULT.md
```

若必须改动 debug 代码，只允许最小兼容修复，并在结果中明确说明。

## 二、API36 AVD 启动

优先复用 `scripts/task15-emulator.ps1` 的隔离 datadir 思路，但不要修改 task15 历史脚本语义。

可以新增：

```text
scripts/task20-emulator.ps1
```

要求：

1. 使用已存在的 AVD 名称。
2. 不 wipe 用户原始 AVD 数据。
3. 使用独立临时 datadir。
4. 启动后轮询 `adb devices`，直到 API36 设备状态为 `device`。
5. 记录 emulator PID、serial、API、product、model、ABI、page size。
6. 如果启动失败、设备为 `offline` 或超时，保存完整诊断：
   - emulator stdout/stderr（如可取得）
   - `adb devices -l`
   - `adb get-state`
   - `adb shell getprop ro.build.version.sdk`（若可连接）
   - 端口/启动超时信息
7. 不要把 emulator userdata、日志或临时镜像加入 Git。

脚本必须拒绝误用 API31：

```text
Require API36
connected device API must equal 36
```
