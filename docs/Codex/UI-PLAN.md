# AppSandbox UI 改造计划

日期：2026-09-23。目标：把当前单页 APK 导入工具改造成清晰、可恢复、适合持续扩展的“应用沙盒工作台”。

当前页面由 `MainActivity` 和 `activity_main.xml` 组成：顶部标题、APK 导入按钮、导入成功后的 Guest 摘要、错误文本。现有功能是通过 Android Storage Access Framework 选择 APK，写入私有 Guest 存储，解析包信息并展示摘要。首期只优化宿主页面，不改变 `GuestStore`、`GuestPackageReader` 和 clean-room 架构边界。

## 1. 产品结构

首页回答三个问题：我能导入什么、最近导入了什么、下一步能做什么。

```text
┌──────────────────────────────┐
│ App Sandbox             设置  │
│ 管理本地 APK 和 Guest 记录    │
│                              │
│ ┌──────────────────────────┐ │
│ │ 选择 APK                  │ │
│ │ 从设备导入一个 APK        │ │
│ └──────────────────────────┘ │
│                              │
│ 最近的 Guest                 │
│ ┌──────────────────────────┐ │
│ │ 图标  应用名称           │ │
│ │       包名 · 版本        │ │
│ │       已导入 / 解析失败  │ │
│ └──────────────────────────┘ │
│                              │
│ 空态：还没有导入 APK          │
└──────────────────────────────┘
```

导入成功后，摘要采用卡片分组：应用身份、版本信息、组件统计、存储路径状态。原始路径和异常堆栈默认收起，必要时通过“查看详情”展开。

## 3. 状态模型

页面至少区分以下状态：

- `Empty`：尚无 Guest 记录，提供导入入口。
- `Selecting`：系统文件选择器已打开；页面不伪造加载百分比。
- `Importing`：APK 正在复制或解析；按钮防重复提交。
- `Success`：显示新的 Guest 摘要，并允许继续导入。
- `Failure`：保留上一次成功摘要，显示失败原因和“重新选择”操作。
- `Partial`：包信息可读但某些字段缺失，明确标注“未提供”，不写成错误。

状态迁移必须由真实回调驱动。Activity 销毁或重建时，晚到回调不能覆盖新的导入结果。

## 4. 交互规则

- 导入按钮文字使用“导入 APK”，副文案说明“从设备选择一个 APK”。
- 导入成功后 Toast 只作为辅助，主要结果放在页面卡片中。
- 错误文本不能只显示 `Exception.message`；给用户行动建议，并把技术详情放在可展开区域。
- 应用图标为装饰元素，应用名称、包名和状态必须可被辅助功能读取。
- 删除 Guest 前显示应用名、包名和内部 Guest ID；删除成功后才从列表移除。
- 选择器取消不显示错误；无效 APK、读取失败和解析失败需要区分。
- 不展示尚未实现的“启动 Guest”“虚拟定位”“通知管理”等入口。

## 5. 验收矩阵

| 维度 | 场景 | 通过标准 |
|---|---|---|
| 页面 | 首次进入 | 标题、说明、导入按钮和空态清晰 |
| 导入 | 有效 APK | 卡片显示图标、名称、包名、版本和组件摘要 |
| 导入 | 取消选择 | 页面保持原状态，无错误提示 |
| 导入 | 非 APK/损坏文件 | 显示可行动错误，允许重新选择 |
| 数据 | 重启应用 | 已导入记录仍可读取，不重复创建 |
| 字体 | 1.0/1.3/2.0 | 内容可滚动，按钮和摘要不重叠 |
| 系统 | API 31/36 | Insets 正确，键盘不遮挡输入或底部操作 |
| 无障碍 | TalkBack | 操作顺序合理，图标不抢焦点，状态可读 |
| 维护 | clean-room | 没有复制其他虚拟化项目的实现或结构 |

## 6. 推荐目录与代码边界

```text
app/src/main/
  java/com/example/appsandbox/
    MainActivity.kt              # 状态协调和导航
    ui/                           # 页面、适配器、状态渲染
    model/                        # GuestPackageRecord 等业务模型
    packageinfo/                  # APK 元数据解析
    storage/                      # 私有存储和记录持久化
  res/
    layout/
    values/
    values-night/
```

UI 层只依赖公开的 `GuestStore` 查询/导入接口和 `GuestPackageReader` 的解析结果；存储层不反向持有 View。若引入 ViewModel，状态应是可序列化的纯数据，避免把 `Drawable`、`Context` 或 Activity 放进状态对象。
